# 猫猫周边义卖收银台

一个为线下义卖现场设计的移动端收银记账工具。工作人员用手机选择商品与数量，页面自动计算优惠组合、应收金额和满赠提示；完成本单后，订单会保存到云端，供所有使用同一地址的工作人员共同查看、管理和导出。

它的职责是“算账、记账、查账”，不接入微信、支付宝、银行卡等支付渠道，也不处理真实资金。顾客付款仍通过现场原有的收款方式完成。

## 功能概览

- 手机竖屏优先的快速收银界面，数量变化会立即反映在购物车和总额中。
- 文字版与商品图版两种浏览方式，共用同一套购物车和结账状态。
- 支持单价、组合优惠和多档优惠，自动选择当前数量下的最低应收金额。
- 根据订单金额动态显示满赠条件、达成状态和结账赠品。
- 结账前可填写选填备注，订单保存成功后再清空当前购物车。
- 全屏历史记录，支持展开明细、左滑删除和多选导出 Excel。
- 云端共享订单与商品目录，多台手机打开同一应用即可看到一致数据。
- 商品可在页面内新增、编辑、停用，并支持上传或更换商品图。
- 连续快速点击数量按钮不会触发常见的手机浏览器双击放大。

## 使用方法

### 开始一单

1. 用手机打开已经部署的收银台网址。
2. 按需要选择“文字版”或“商品图版”。
3. 点击商品旁的“＋ / −”调整数量。
4. 通过底部购物车查看已选件数和实时金额。

### 核对并完成

1. 点击购物车核对已选商品。
2. 点击“看结账单”，检查明细、金额与赠品提示。
3. 根据需要填写备注；备注可以留空。
4. 确认顾客已经通过现场收款方式付款后，点击“结束本单”。
5. 页面提示保存成功后，点击“开始下一单”。

在保存前都可以返回修改或清空订单。云端保存失败时，页面不会把本单误判为已完成，可在网络恢复后重试。

### 历史记录与导出

- 点击页面底部的“历史记录”进入全屏记录页。
- 点击记录可展开商品件数和备注；向左滑动可显示删除操作，向右滑动可收回。
- 点击右上角“导出”，勾选部分订单或使用“全选”，即可生成 `.xlsx` 文件。
- 导出表包含时间、商品详情、金额与备注，适合对账、汇总和留档。

### 编辑商品

点击“编辑商品”可以维护共享商品目录，包括名称、单价、可选优惠档位和商品图。商品图可以暂时留空；上传时会先在浏览器中压缩，再写入云端记录。新增或修改完成后，其他工作人员刷新页面即可看到更新。

## 系统架构

本项目采用轻量的前后端分离结构，适合部署到带云数据库与服务端函数的网站应用平台：

```text
手机 / 桌面浏览器
        │
        ▼
单页前端（HTML + CSS + JavaScript）
  ├─ 商品展示与视图切换
  ├─ 购物车、优惠计算与满赠规则
  ├─ 结账、备注与历史记录交互
  └─ 浏览器端 Excel 生成
        │  同源 HTTP API
        ▼
服务端函数 / API 层
  ├─ 参数校验与幂等控制
  ├─ 订单读写与删除
  └─ 商品读写与软删除
        │
        ▼
云数据库
  ├─ charity_orders
  └─ charity_products
```

### 前端层

前端集中在 `index.html` 中，包含页面结构、移动端样式和业务脚本，不依赖构建工具。静态资源放在 `assets/`。这种组织方式便于直接导入网站应用平台，也方便现场紧急更新。

主要前端模块包括：

- **状态管理**：维护当前商品目录、购物车数量、视图模式、结账状态和历史记录状态。
- **计价引擎**：把单价与优惠档位视为不同的组合方案，根据购买数量计算最低价格，避免工作人员手工拆分套餐。
- **持久化适配**：通过 `/api/orders` 和 `/api/products` 与云端通信；只有服务端确认成功后才更新完成状态。
- **交互层**：处理固定购物车、全屏历史页、滑动删除、商品编辑和移动端触控行为。
- **导出层**：在浏览器中生成 Office Open XML 工作簿并下载，不需要把订单发送给第三方表格服务。

### 云端数据模型

#### `charity_orders`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 订单唯一标识，用于幂等保存 |
| `timestamp` | integer | 下单时间戳 |
| `total` | integer | 订单金额，单位为分 |
| `count` | integer | 商品总件数 |
| `items` | array | 商品名称、数量和小计等快照 |
| `note` | string | 选填备注，最多 200 字 |
| `createdAt` | server timestamp | 服务端创建时间 |

#### `charity_products`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 商品唯一标识 |
| `name` | string | 商品名称 |
| `price` | integer | 单价，单位为分 |
| `deals` | array | 最多两档组合优惠 |
| `rule` | string | 前端展示用的计价说明 |
| `image` / `imageData` | string | 内置资源名或压缩后的图片数据 |
| `deleted` | boolean | 软删除标记 |
| `sortOrder` | integer | 商品排序值 |
| `updatedAt` | integer | 最近更新时间 |

金额统一以整数“分”存储和运算，避免浮点数造成小数误差；展示时再格式化为元。

### API 约定

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/orders` | 按时间倒序读取订单 |
| `POST` | `/api/orders` | 幂等创建订单 |
| `DELETE` | `/api/orders/:id` | 删除指定历史订单 |
| `GET` | `/api/products` | 按排序读取商品记录 |
| `POST` | `/api/products` | 新增商品 |
| `PUT` | `/api/products/:id` | 更新或写入商品记录 |
| `DELETE` | `/api/products/:id` | 删除商品记录 |

更完整的字段、索引和限制见 [`workbuddy-cloud-spec.json`](./workbuddy-cloud-spec.json)。服务端应验证字段类型、数量和请求体大小，并保证相同订单 `id` 的重试不会产生重复记录。

### 默认数据与云端配置合并

前端内置一份基础商品目录，但不会要求部署时把整份目录重复写入数据库。加载页面时，系统会把内置目录与云端记录按 `id` 合并：

1. 未被修改的内置商品继续使用前端默认配置。
2. 云端同 `id` 记录覆盖对应默认项，用于同步编辑结果。
3. 云端新增记录追加到目录中。
4. `deleted: true` 作为删除墓碑，阻止已删除的内置商品在刷新后重新出现。

该策略既保证首次部署即可使用，也避免新增商品覆盖原目录。

## 部署

本项目需要云端数据服务才能让不同手机共享历史记录和商品目录。推荐使用 WorkBuddy 的“网站应用”模式部署，不要只做纯静态托管。

1. 将项目完整打包并上传到 WorkBuddy。
2. 要求其读取 `WORKBUDDY_DEPLOY.md` 和 `workbuddy-cloud-spec.json`，创建或升级云数据库与同源 API。
3. 开启云数据库，不需要用户登录或大模型能力。
4. 更新已有应用时必须保留 `charity_orders` 和 `charity_products`，不可清空原数据。
5. 发布后使用两台手机测试订单、备注、历史记录、商品编辑和删除是否同步。

详细部署提示与验收项目见 [`WORKBUDDY_DEPLOY.md`](./WORKBUDDY_DEPLOY.md)。

## 更新已有版本

- 仅调整界面或前端逻辑时，可以更新 `index.html` 与相关静态资源，但仍需保持现有 API 路径和数据结构。
- 修改字段或接口时，应同步更新 `workbuddy-cloud-spec.json`，并先做兼容性迁移。
- 不要用空表覆盖线上表，不要把云端共享数据改回 `localStorage`、`sessionStorage` 或 IndexedDB。
- 更新后至少执行一次跨设备共享测试和一次 Excel 导出测试。

## 安全与使用边界

- 当前设计为“持有链接即可使用”，没有工作人员账号体系；访问链接应只发给相关工作人员。
- 订单和商品的新增、编辑、删除会影响所有访问者，重要活动建议定期导出 Excel 备份。
- 管理员密钥、数据库 Secret 和 API Key 必须只保存在服务端环境，不得写入 `index.html`。
- 商品图片数据和请求体应设置大小限制，服务端需要执行类型、范围与长度校验。
- 本项目不发起支付、不验证到账，也不承担支付终端或财务系统的职责。

## 上线前检查

- 两台手机打开同一地址，可以看到一致的订单和商品目录。
- 订单保存失败时，当前订单不会被清空或显示为已完成。
- 商品增删改、订单删除和备注可以在刷新后保持一致。
- 文字版、商品图版、购物车、结账单和满赠提示状态一致。
- 历史记录可展开、左滑可恢复、选择记录可正常导出 `.xlsx`。
- 手机连续点击“＋ / −”只改变数量，不触发页面放大。
